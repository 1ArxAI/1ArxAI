# Use a serializable plan object to separate agent reasoning from tool execution

An agent that plans first and then executes can be paused, inspected, or replayed without re-running the model.

```python
from dataclasses import dataclass
from typing import Literal

@dataclass
class PlanStep:
    tool: str
    args: dict
    depends_on: list[int] = None

@dataclass
class AgentPlan:
    steps: list[PlanStep]
    reasoning: str

def plan(llm, prompt: str) -> AgentPlan:
    # LLM returns structured plan, not tool calls
    return llm.with_structured_output(AgentPlan).invoke(prompt)

def execute(plan: AgentPlan, tools: dict) -> list:
    results = {}
    for i, step in enumerate(plan.steps):
        deps = step.depends_on or []
        step_args = {**step.args, **{f"step_{d}": results[d] for d in deps}}
        results[i] = tools[step.tool](**step_args)
    return results
```

- Planning and execution are decoupled so you can log, version, or replay the plan without re-prompting the LLM
- Dependencies between steps are explicit in the plan, not hidden in prompt text
- The plan is serializable JSON, making it trivial to persist, audit, or feed to a smaller model for verification
