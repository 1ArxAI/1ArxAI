Route each task to the smallest model that meets your quality threshold instead of defaulting to the largest. A cost-aware router cuts spend by 60-80% with negligible quality loss on structured tasks.

```python
from dataclasses import dataclass
from enum import Enum

class ModelTier(Enum):
    SMALL = "gpt-4o-mini"
    MEDIUM = "gpt-4o"
    LARGE = "o1"

@dataclass
class TaskSpec:
    requires_reasoning: bool
    max_tokens: int
    json_schema: bool

TIER_THRESHOLDS = {
    ModelTier.SMALL: TaskSpec(requires_reasoning=False, max_tokens=4096, json_schema=True),
    ModelTier.MEDIUM: TaskSpec(requires_reasoning=False, max_tokens=16384, json_schema=True),
    ModelTier.LARGE: TaskSpec(requires_reasoning=True, max_tokens=32768, json_schema=False),
}

def route_model(spec: TaskSpec) -> ModelTier:
    for tier in (ModelTier.SMALL, ModelTier.MEDIUM, ModelTier.LARGE):
        threshold = TIER_THRESHOLDS[tier]
        if spec.requires_reasoning and not threshold.requires_reasoning:
            continue
        if spec.max_tokens > threshold.max_tokens:
            continue
        if spec.json_schema and not threshold.json_schema:
            continue
        return tier
    return ModelTier.LARGE
```

- Define explicit capability tiers with concrete limits (tokens, schema support, reasoning) instead of vibes.
- Route at call time: extraction, classification, and formatting rarely need a reasoning model.
- Log the tier chosen per request so you can audit whether the router is too aggressive or too conservative.
