Avoid async context leakage by binding task-scoped data to the async call chain instead of globals. When an agent fans out multiple LLM calls, a request-scoped contextvar carries trace IDs, user identity, and budget so every downstream call sees the same scope without thread-local pollution.

```python
from contextvars import ContextVar
from dataclasses import dataclass, field
from typing import Optional

_request_ctx: ContextVar[Optional["RequestContext"]] = ContextVar("_request_ctx", default=None)

@dataclass
class RequestContext:
    trace_id: str
    user_id: str
    token_budget: int
    spent: int = 0

def set_request_context(ctx: RequestContext) -> None:
    _request_ctx.set(ctx)

def get_request_context() -> RequestContext:
    ctx = _request_ctx.get()
    if ctx is None:
        raise RuntimeError("Request context not set")
    return ctx

async def call_llm(prompt: str, model: str) -> str:
    ctx = get_request_context()
    # ctx.trace_id automatically flows to logs, retries, and cost tracking
    return await _do_call(prompt, model, trace_id=ctx.trace_id)
```

- ContextVar isolates scope per async task chain; no global state leaks across concurrent requests.
- Attach trace_id, user_id, and budgets at the entry point (API handler, queue consumer) so every tool call inherits them.
- Read the context in logging middleware, retry policies, and cost guards without passing arguments through every layer.
