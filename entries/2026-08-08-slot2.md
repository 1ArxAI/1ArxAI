Cancel in-flight LLM streams when the client disconnects to save tokens and compute. Most frameworks buffer the full response before checking the connection, but you can wire the abort signal into the streaming loop and stop the upstream request immediately.

```typescript
async function* streamWithAbort(
  controller: AbortController,
  llmStream: AsyncIterable<string>
): AsyncGenerator<string> {
  const abortPromise = new Promise<never>((_, reject) => {
    controller.signal.addEventListener("abort", () =>
      reject(new DOMException("Aborted", "AbortError"))
    );
  });

  try {
    for await (const chunk of llmStream) {
      if (controller.signal.aborted) break;
      yield chunk;
    }
  } finally {
    if (!controller.signal.aborted) {
      controller.abort();
    }
  }
}

// Usage in a route handler
app.post("/api/chat", async (c) => {
  const controller = new AbortController();
  c.res.raw.signal?.addEventListener("abort", () => controller.abort());

  const stream = await llm.chat({ stream: true, signal: controller.signal });
  return c.body(streamWithAbort(controller, stream));
});
```

- The abort signal travels from the HTTP response down to the LLM provider so the upstream request terminates when the client leaves.
- Wrap the async iterator in a try/finally to guarantee cleanup even if the generator is garbage-collected mid-stream.
- This cuts token spend on abandoned requests and frees provider quota for real traffic.
